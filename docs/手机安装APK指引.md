# 手机安装与离线扫描

## 当前版本：手机独立运行（0.2.3-local / code203）

适配目标：**iQOO Neo8 Pro，Android 15**。安装文件为项目 `releases/SnapScan-offline-local-0.2.3.apk`，支持 arm64-v8a 手机，最低 Android 8。该文件是包含全部模型的 APK，WGT 不能替代它。模拟器使用另行构建的 x86_64 调试包，不增加手机安装包体积。本版修复课本正文漏行、裁剪混入邻行及相邻正文排序，加入自动小区域误裁保护，继续保留此前翻拍检测与文字提取功能。

1. 将带 `0.2.3` 文件名的 APK 复制到手机，在系统文件管理器中打开安装。当前开发包沿用上一版开发签名，版本号提升到203，可覆盖相同包名、相同签名的0.2.0、0.2.1或0.2.2开发包；安装后在系统应用信息中确认版本为 `0.2.3-local`。若系统提示签名不匹配，应先确认是否装的是原始正式包；卸载会清空其本地内容，请先自行保存需要的数据。
2. 安装后可直接关闭 WiFi 和移动数据，再打开“智拍 SnapScan”。首页应显示“手机本地引擎 / 完全离线”，并在模型检查后显示 `rec_head_v1` 就绪。首次运行也无需下载模型、填写电脑 IP 或启动后端。
3. 点“拍照扫描”，按系统提示授权相机；或点“从相册选”通过系统文件选择器选择一张照片。相册读取使用用户明确选择的文件，不要求授予整个相册读取权限。
4. 查看扫描预览：检查纸张外沿，必要时拖动四角或输入坐标。选择“原色 / 净白 / 黑白”，改动后点“应用裁切与效果”。自动候选小于整图10%时会保留整图并提示手调，避免只剩标题或内部表格；小票本身很小时也需手调。没有可靠边界时，手动调整，或明确选择保留整图。
5. 只需要图像时，点“保存扫描图到相册”，文件进入系统相册的 `Pictures/SnapScan`；此步骤不运行 OCR。
6. 需要文字时，点“确认并提取文字”。手机在本机处理当前扫描图；模型加载或图像读取失败会停止并提示，不切换到电脑或云端。
7. 结果页将同行文字按从左到右排列，可逐行校对并保存，原文字框索引和坐标保持不变。复制与纯文本 PDF 使用相同阅读顺序；保留版式 PDF 使用扫描图加可搜索文字层，Excel 仍导出原框顺序的 OCR 明细，不恢复表格单元格。点击“打开文件 / 分享文件”通过系统选择对应应用；PDF 阅读器或 Excel 阅读器需由手机自行提供。
8. 退出并重开 App，在历史中搜索票据文字并打开，核对图片、校对结果及导出仍可使用。已有文字框会采用新阅读顺序；**此前漏字的记录需要用原图重新扫描，重新导出旧记录不能补回漏字。** 此前导出的 PDF 不会自动改写。段落和多栏阅读顺序仍需人工核对。

**安装包校验：**82,177,906 字节；SHA-256 为 `25b6217d35e3f10895b04e036b58e1428952fbe630b2c2c2bf760ad88b9fc0c3`。

**验证范围：**25 项 Android 测试在独立 Android 15 x86_64 模拟器中关闭无线网络执行，另通过 2 项 JVM 单元测试并检查 APK 无 INTERNET 权限；模拟器覆盖升级检查保留了旧8条记录和208个私有文件。当前没有连接你的 iQOO 实机，因此尚未测得该机的实际识别耗时、相机返回行为及系统分享兼容性。详细执行结果以 `reports/android_local_device_verification.json`、`reports/android_local_build_verification.json` 及 [三类扫描评测报告](../reports/课本漏字修复与三类新数据评测.md) 为准。

**历史版本：**`0.2.1-local` / code201 的翻拍检测修复原因和验证限制见 `reports/屏幕翻拍检测修复说明.md`；原安装包及对应证据见 0.2.1 归档清单（本地资料，未随仓库公开）。

**图像边界：**你提供的小票上下贴着画面边缘，并叠在另一张纸上。新版按可见纸面去除木纹背景，不生成画外内容；可能保留下层纸条。只要最上方那张时，需要手动调四角。折叠、严重卷曲、同色背景或被遮挡纸张仍可能检测失败。

模型、SQLite 历史及导出在手机私有目录中。旧电脑后端中的历史不会自动迁入手机；需要保留的结果先从旧版导出。卸载独立 App 或清除其数据会删除尚未保存到相册/其他位置的内容。

## 以下为旧局域网版本指引（仅开发对照）

以下步骤只适用于 `SnapScan-rec-head-v1-scan-imaging.apk` 等旧包，**不适用于上面的独立版**。

2026-10-15 实测电脑 WLAN 地址为 `192.168.58.120`。手机和电脑应连接可互通的同一 WiFi/热点；换网络后重新确认电脑 WLAN 地址，不使用 VMware/VPN 虚拟网卡地址。

## 启动电脑后端

双击项目根目录 `run_backend.bat`。手机浏览器访问 `http://192.168.58.120:8000/api/health`，应看到 `status: ok`、`ocr.ready: true`、`ocr.model.id: rec_head_v1`。

扫描成像和 OCR 模型运行于电脑，手机无需安装训练框架。手机与电脑必须保持局域网互通；电脑后端关闭后，手机不能执行扫描处理或识别。这是无需公网的本地协作架构，不是完全独立于电脑的手机推理应用。

## APP 操作

1. 展开首页的后端“设置 +”，填写 `http://192.168.58.120:8000`，点“保存地址”和“检测连接”。
2. 检测提示应包含模型 `rec_head_v1` 已就绪。若失败，按具体错误检查模型文件、电脑服务、地址及网络。
3. 点“拍照扫描”或“从相册选”，允许相机/相册权限。
4. 拍照后先查看扫描预览，不会立即识别。切换“原图 / 调整边界”与“扫描效果”，核对自动检测的纸张外沿。四角应包住完整纸张；可拖动四角，也可展开坐标输入精调。
5. 选择“原色 / 净白 / 黑白”，分别对应 `color / clean / bw`。边界或模式修改后点“应用裁切与效果”，成功后才能继续。若未检测到可靠边界，必须手动调整并应用，或明确选择“保留整图”；保留整图仍包含原有背景。
6. 点击扫描效果可放大检查。只需要图像时，点“保存扫描图到相册”即可，不运行 OCR，也不新增识别历史。保存被拒绝时按提示检查相册/照片权限。
7. 确认效果后点“确认并提取文字”。处理图下载失败会停止，需重试，不会悄悄识别原照片。结果页对照实际识别的扫描图逐行纠错，点击文字行可高亮对应区域；模型信息应显示 `rec_head_v1`。
8. 点击“保存校对”，或直接导出时自动先保存；保存失败会保留草稿并停止导出。“保留版式 PDF”保留扫描图并加入文字层，“纯文本 PDF”重排文字；“OCR 明细 Excel”导出校对后的逐行结果，不是表格恢复。
9. 历史条目可打开继续校对和导出；旧记录没有扫描图时仅能导出纯文本 PDF。纠错只改变文字层，不会改写扫描图中的字形。首页原照片用于裁切对比，校对记录保存实际识别的扫描图。

新版会显示拍照或相册调用失败的具体原因；用户主动取消不会误报失败。首次真机验收仍需检查拍照与权限、四角拖动、三种效果、只保存图像、确认提取及历史导出的完整流程。本轮代码与构建验证不代表已通过真机验收，也不证明 CER 或实际识别精度提升。

新版会保存后端地址，换 WiFi 后直接在首页修改，无需因 IP 变化重新打包。旧 APK 固定使用 `192.168.56.120:8000`，没有此地址设置功能。

若手机浏览器无法访问健康接口，先解决局域网连接：确认端口 8000 的防火墙规则、VPN 路由及校园网 AP 隔离。模型部署、校验和回滚说明见 `backend/models/README.md`。
